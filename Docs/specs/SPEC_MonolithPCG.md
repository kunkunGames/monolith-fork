# Monolith - MonolithPCG Module

**Parent:** [SPEC_CORE.md](../SPEC_CORE.md)
**Engine:** Unreal Engine 5.7+
**Version:** 0.20.4
**Status:** Implemented

---

## 1. Purpose

`MonolithPCG` owns 28 `pcg` actions spanning AssetRegistry discovery, typed `UPCGGraph` asset authoring and read-back, atomic scalar graph user-parameter schema/default authoring, exact static-subgraph assignment, identity-preserving complete graph-content replacement, structural validation, guarded copied-graph soft-reference migration, Actor Blueprint PCG-component-template graph assignment, and the editor-world `UPCGComponent` lifecycle. Eleven of those actions form the component surface. Authoring uses public PCG graph/node/pin/component and `FInstancedPropertyBag` APIs rather than reflected writes to graph topology. Component actions configure an exact SCS template or create/configure exact-path live instances, assign graphs, schedule and inspect asynchronous generation, refresh/cancel/clean generated state, summarize bounded output/resources, and atomically edit graph-instance user-parameter overrides.

## 4. Typed authoring contract

1. Normalize the destination to a top-level project-owned mounted package and exact package-leaf object path.
2. Resolve settings types from live reflection. Reject abstract/deprecated classes and ambiguity; accept canonical class paths.
3. Reject hidden/library-internal settings types. Preflight every settings leaf against edit flags, instance `CanEditChange` (including its full property chain), and a transient duplicate written by the canonical strict reflection walker. For an `FClassProperty`, require an exact class-path string and stage `FClassProperty::ImportText_Direct` before the walker write so UE enforces the property's `MetaClass` contract (for example, `TSubclassOf<AActor>` rejects `UTexture2D`) without mutating the live settings object.
4. Apply settings one leaf at a time under matching `PreEditChange(FEditPropertyChain)` / `PostEditChangeChainProperty` callbacks so PCG settings that rebuild pins or cached data receive the same property identity as editor Details-panel edits.
5. Author graph user parameters only through `set_pcg_graph_user_parameters`. Every upsert requires an exact `FInstancedPropertyBag::IsPropertyNameValid` name, one of `bool`, `byte`, `int32`, `int64`, `float`, `double`, `name`, or `string`, and an explicit non-null `default_value`; missing defaults are never synthesized. Stage all add/update/type-change/remove operations on a copied `FInstancedPropertyBag`, reject invalid names, unknown removals, and duplicate/conflicting names, then commit once through `UPCGGraph::UpdateUserParametersStruct`. Dry-run defaults true, string values are capped at 4,096 characters, full-range `int64` defaults use canonical decimal strings, and validation/save failure restores the original bag and package dirty state.
6. Assign a static subgraph only through `UPCGBaseSubgraphSettings::SetSubgraph`; generic reflected settings writes are not a substitute for the `SubgraphInstance` contract. Require the exact case-sensitive canonical object path of a project-owned `UPCGGraph` or `UPCGGraphInstance`; redirectors, aliases, and case-only variants fail closed. Reject an active override, honor the parent graph's asset filter, reject self/recursive hierarchies, and verify both the exact assigned interface and concrete graph. Incident topology must remain exactly equivalent by endpoint identity and pin label; if the new subgraph invalidates an edge, the caller must disconnect/reconnect explicitly. Dry-run is side-effect free, and rollback restores the previous interface, incident edges, and package dirty state.
7. Replace a complete graph only through `replace_pcg_graph_contents`. Source and target must be distinct exact canonical project-owned assets whose concrete class is exactly `UPCGGraph`; source and target node/edge counts must fit caller bounds, and both packages must be clean. Reject an already-recursive source and any source that contains the target, because remapping that donor root into the target would create a recursive static-subgraph hierarchy. Build and structurally validate a verified transient preview first. On commit, map the source root to the existing target root through `FObjectDuplicationParameters::DuplicationSeed`, allowing CoreUObject to remap the entire reflected inner-object graph—including cross-node settings references—while reusing target default input/output subobjects and preserving the target path/pointer. Before each seeded replay, reset the reusable target root and every source-relative inner object matched by the complete outer/name/class lineage to their exact archetype values for every duplicable property; CoreUObject delta serialization omits source values equal to the archetype, so this generic baseline is required to replace or roll back a previous non-default value exactly while leaving unmatched target-only editor objects untouched. Build that reusable-object set with one nested-object enumeration per root and a relative-lineage index; recursively rescanning the global UObject array once per graph inner is prohibited because large authored graphs contain thousands of embedded pins/settings. Verify persistent equality with the bounded canonical object-graph comparator: index each owned UObject once, visit each reachable owned pair once, serialize each duplicable reflected property once, normalize owned references to exact relative lineage, and retain exact paths for external references. At the target root only, `UPCGGraphInterface::LastEditedDocuments` is identity-bound editor workspace state rather than donor graph contents: exclude only that property from source/target equality and preserve the target's original value through preview, commit, rollback, save, and reload. This explicit ownership boundary does not authorize node-, pin-, or type-specific skips; every donor-owned persistent property remains exact. Never use recursive `PPF_DeepComparison` for this graph because shared/cyclic references can repeatedly expand the same pair. Fail closed above 250,000 graph-owned objects, 256 outer levels, or 128 MiB of canonical property payload per graph. Rebind native PCG node delegates, invalidate graph compiler/runtime caches, structurally validate, and save only after `dry_run=false` plus `confirm=true`.
8. Mutate graph structure only through `UPCGGraph::AddNodeOfType`, `RemoveNode`, `AddLabeledEdge`, and `RemoveEdge`. Reject self/cyclic edges, implicit replacement of single-connection inputs, and connections that require an implicit filter/conversion node.
9. Batch graph editor notifications with RAII, prime compilation state before edits, re-enable notifications before emitting the strongest supported external-modification notification, and confirm the actual post-mutation topology. Never interpret `AddLabeledEdge`'s boolean as success.
10. Snapshot the exact root settings values, incident topology, complete graph object state, object identity, and package dirty state needed by each mutation. On property, topology, subgraph-assignment, graph-replacement, structural-validation, or save failure, explicitly restore that snapshot before returning an error.
11. Run bounded structural validation before every save. This in-handler pre-save check is the authoritative commit boundary; the actions deliberately do not use a late execution-guard validator because a failure after persistence cannot roll back the package file. Save through `UEditorAssetSubsystem::SaveLoadedAsset`, then require a non-empty package file when persistence was requested.
12. Return stable `node_id` values (`__input__`, `__output__`, or the element UObject name), authored titles, pin labels, settings/interface class paths, mutation status, and save evidence.

### 5.1 Action schemas and result evidence

`generation_task_id` and `cleanup_task_id` are always JSON strings. Their paired `*_task_valid` boolean determines whether the string represents a live engine task; an invalid task uses `false` plus an empty string rather than a JSON number or numeric sentinel.

### 5.2 Lifecycle invariants

1. Resolve `actor_path` and `component_path` as exact live UObject paths in the active editor world. Labels, short names, substring matches, stale pointers, and cross-world objects are rejected. `list_components` supplies the canonical paths for follow-up calls; actions resolve them again on every invocation because reconstruction and undo/redo can replace component instances.
2. `APCGPartitionActor` is engine-owned and cannot host `create_component`. Every component owned by an `APCGPartitionActor` is inspection-only regardless of whether its local-component flag is currently set: `get_component` and `get_component_output` accept its exact path and expose `original_component_path`; all seven component-targeted mutation actions reject it and direct the caller to that original component.
3. Create components transactionally in the canonical order: validate every requested field/graph/save target and name collision; allocate the exact-name instance; apply initial scalar settings; call `AddInstanceComponent`; register; apply and verify partitioning; run `CanGraphInterfaceBeSet`; assign the graph; verify the complete postcondition; dirty/save. A complete rollback restores the original object/package dirty bits. If removal or state restoration is incomplete, the surviving component, actor, level, and owning packages stay explicitly dirty so no partial live mutation can be hidden. Existing same-name objects are an explicit error unless `return_existing` finds an exact configuration match; implicit reuse or rename is forbidden.
4. Load graph assets through the canonical typed asset-path contract. Assignment requires an editable graph-instance property in the current editor/Level Instance context, rejects recursive `UPCGGraphInstance` chains through `CanGraphInterfaceBeSet`, uses the public `UPCGComponent` graph interface, verifies exact read-back, and never substitutes a default or legacy graph. Component/level persistence occurs only when `save=true`; save failure restores the pre-action component state and package dirty state before returning an error. A value-identical `save=true` request must still pass the same idle/ungenerated mutation guard before any save; a no-op cannot be used to persist an active generated component.
5. `set_blueprint_component_graph` is the only persistent Blueprint-template route. Resolve an exact project-owned Actor Blueprint, require exactly one SCS node whose variable name equals `component_name` and whose component template is a `UPCGComponent`, and reject aliases, inherited/runtime instances, ambiguity, missing graph instances, and recursive graph-interface chains. Omitted `dry_run` is side-effect free; a changed commit requires `dry_run=false` plus `confirm=true`. Prepare source control only after the change/confirmation gates, modify the Blueprint/template/graph instance, call `SetGraphLocal`, mark and compile the Blueprint, re-resolve the reconstructed SCS template, and require exact graph read-back plus non-error compile status. Save only when requested. Compile, read-back, or save failure restores the previous interface, recompiles, verifies rollback, restores the original dirty bit on complete rollback, and leaves the package dirty when rollback is incomplete.
6. Configuration writes expose only the supported PCG component contract, stage every requested field before mutation, validate the final combination, apply all fields under one transaction, and verify normalized read-back. At least one setting is required; `generate_on_drop_when_on_demand=true` is valid only with `generation_trigger=on_demand`, and `partitioned=true` requires `CanPartition()`. A partially valid request never produces a partial component edit.
7. `generate_component`, `refresh_component`, `cancel_component`, and `cleanup_component` call the native UE 5.8 component lifecycle APIs and return promptly. Generation and cleanup are asynchronous: a scheduling action returns state plus any `FPCGTaskId` as a decimal JSON string so the full 64-bit value survives JSON clients. Callers poll `get_component`; handlers never sleep, spin, tick the editor manually, or busy-wait on the game thread.
8. Generation calls `GenerateLocalGetTaskId(force)` and leaves the final eligibility decision to UE's private `ShouldGenerate` state machine. Monolith classifies only the canonical already-generated, unpartitioned, non-dirty, non-force decline as an up-to-date no-op; dirty generated state is not short-circuited, so UE can schedule regeneration.
9. Refresh has only `component_path`. It calls native `Refresh(EPCGChangeType::None, false)`, never replaces/cancels an existing refresh, and returns `already_refreshing=true` plus `coalesced=true` when a refresh is active. A cleanup request that finds native cleanup already running reports `requested_remove_components`, `inflight_remove_components_known=false`, and `coalescing_status="already_cleaning_mode_not_observable"`; it never relabels the new request as the unknown mode of the in-flight task. `cancel_component` owns generation cancellation only and rejects refresh-in-progress, cleanup-in-progress, and runtime-scheduler-managed components instead of pretending those operations are cancellable.
10. `get_component` is the polling boundary. It reports generated/generating/cleaning/refresh state and the currently known generation/cleanup task ids as decimal strings. A missing or invalid engine task id is reported explicitly rather than converted to an unsafe numeric sentinel. Managed-resource count enumeration is potentially expensive and therefore opt-in through `include_managed_resource_count=true`; the default reports that the count was not requested.
11. `get_component_output` rejects reads unless `get_component` reports `output_accessible=true`, which requires generation, cleanup, and refresh to be idle. Output rows, each row's sorted tags, managed-resource rows, and each resource's managed-object rows have independent 1-500 limits. Each tag array reports `tag_count`, `tag_returned`, the applied `tag_limit`, and `tags_truncated`; a caller must not infer completeness from the array alone. Existing aligned cached CRC values may be reported; inspection does not calculate new CRCs or synchronously load resource references.
12. Managed-resource inspection first checks `AreManagedResourcesAccessible()`. The locked iteration callback copies only stable scalar state and soft object paths; it does not re-enter PCG, load objects, or retain resource pointers after the callback.
13. `set_component_user_parameters` edits overrides on the component's `UPCGGraphInstance`, not the source graph schema. Every named value is resolved against the current property-bag descriptor and parsed into a copied bag before touching the live instance. Supported scalar string/export-text input and output are capped at 4,096 characters, floating-point input must be finite and a `float` must fit its finite 32-bit range. `int64` JSON numbers must be integral and inside `[-(2^53-1), 2^53-1]`; full-range values use a canonical decimal string with no sign prefix, whitespace, redundant leading zero, negative zero, overflow, or trailing text. Exact decimal strings are preserved in read-back. Parameter rows are name-sorted and bounded by `user_parameter_limit`, and every serialized/value field exposes truncation evidence where applicable. Apply/clear operations commit as one atomic batch, preserve an explicit override even when its value equals the parent, remove the override id when clearing, verify canonical value and override-state read-back, and restore the original bag/override state on any failure.
14. Mutation responses intentionally omit the potentially large `user_parameters` array. Call `get_component(include_user_parameters=true)` explicitly when parameter rows are needed. Component creation, graph/configuration writes, and user-parameter writes support explicit owning-level persistence; execution-state operations do not imply persistence, and output inspection is read-only.
15. For a newly created component, the preferred persistent sequence is `create_component` without a graph, `set_component_settings`, `set_component_graph`, then separate `get_component` polling. If graph assignment occurs before later settings work, poll until `refresh_in_progress=false` before the next mutation. Every action returns exact identity and state evidence for that decision without a silent fallback.
16. The nine component actions that can mutate or schedule work own source-control preparation at the handler boundary. After validation/no-op/coalescing classification and before the first mutation or schedule, they prepare the exact project package owned by the live component or Blueprint template; transient/non-project packages and unavailable providers are reported as explicit structured skips. The global execution guard suppresses its earlier coarse parameter/result scan only for those registered actions, while retaining dirty-package tracking and audit evidence. Asynchronous PCG completion may create additional partition/external packages that are not knowable at scheduling time; callers must validate the final changelist after completion.

## 6. Safety and bounds

| Gate | Requirement |
|---|---|
| Package boundary | Only mounted packages whose resolved files are inside the current project directory are accepted for typed mutation. Subobjects and mismatched package/object leaves are rejected. |
| Rerun policy | Create/add default to `fail`. `return_existing` is allowed only for the same graph type or same authored-title settings class. |
| Topology | Special graph input/output nodes cannot be removed. Both endpoints must belong to the graph; labels, direction, and directly compatible PCG data types must match. Self/cyclic edges and implicit single-input replacement are rejected; callers disconnect explicitly first. |
| Settings | Only editable, non-transient, non-deprecated, non-edit-const properties accepted by the concrete settings instance and full property chain are writable. Dry-run stages the same write on a transient duplicate and is side-effect free. Class-valued leaves must be exact strings and pass the engine `FClassProperty` `MetaClass` import contract before apply. |
| Validation | Duplicate ids/edges, ownership, missing settings, endpoint-pin ownership, attachment at both ends, directions/types, single-input overflow, and directed cycles are checked before save. Cycle detection is linear in graph size; issue arrays are bounded and expose total/returned/truncated counts. |
| Bounds | Element nodes are capped at 5,000, graph edges at 20,000, node types at 1,000, and validation issues at 1,000 per returned severity array. Read-back property/array/node/edge/pin bounds are caller-clamped, and `response_item_limit` is shared across node, pin, edge, and nested-settings serialization. |
| Migration | Reference remap defaults dry-run, requires confirmation for writes, enforces project ownership and object/reference caps, and reports unsupported dynamic containers. |
| Static subgraph | `set_pcg_subgraph` accepts only the exact case-sensitive canonical path of a project-owned graph/interface on `UPCGSubgraphSettings`; redirectors and path aliases are rejected. It rejects active overrides, filtered targets, and recursive hierarchies, then requires exact interface/concrete-graph read-back. Dry-run and unchanged requests do not dirty or save; failed commits restore assignment, incident edges, and dirty state. |
