## MonolithSource

**Dependencies:** Core, CoreUObject, Engine, MonolithCore, SQLiteCore, EditorSubsystem, UnrealEd, Json, JsonUtilities, Slate, SlateCore

**Note:** Module structure was flattened — the vestigial outer stub has been removed. MonolithSource registers 33 actions. ### Auto-Reindex on Hot-Reload (F17)

**Important:** `monolith_reindex` is the **asset/project** indexer (Blueprints, materials, textures via `MonolithIndex`). It does NOT update the C++ source DB. Source-symbol freshness is owned by this module via:

1. `source.trigger_reindex` — full clean rebuild (engine + shaders + project).
2. `source.trigger_project_reindex` — incremental, project C++ only. Before indexing project `Source` and project-plugin `Source` roots, the indexer prunes existing indexed files under those roots plus dependent `symbols`, `"references"`, `inheritance`, `includes`, source FTS rows, `source_override_edges`, and matching `crg_*` projection rows. Reference ids are snapshotted before deletion, so a reference row owned by a pruned file removes its derived CRG edge even when both endpoint symbols are retained; both surviving endpoints enter the temporary pending set so completion refresh recomputes their metrics. The same pending set retains affected old-neighbor symbol ids for references removed with pruned symbols. This prevents duplicate project symbols or stale native-reference CRG edges from accumulating while preserving engine/shader rows for cross-reference resolution. Offline `monolith_query.exe source trigger_project_reindex` is a DB-free live-only guidance action and does not mutate `EngineSource.db`.
3. **F17 auto-hook (2026-04-26):** `UMonolithSourceSubsystem` listens on `FCoreUObjectDelegates::ReloadCompleteDelegate`. After every Live Coding patch and after every UBT-driven editor restart that fires hot-reload, the subsystem auto-kicks `TriggerProjectReindex()` (async). Guarded by a 5-second cooldown and an in-flight `bIsIndexing` flag so multi-module reload bursts don't storm. Skips silently if `EngineSource.db` doesn't yet exist (first-install bootstrap requires a manual `source.trigger_reindex`).

After F17, agents do not need to invoke any source-reindex action manually in the common dev loop — just run UBT or Live Coding and `source_query` reflects the new symbols within ~1 second. On project source indexing completion, `FMonolithSourceIndexer` calls `FMonolithSourceDatabase::RefreshCrgCacheForFiles` for the newly indexed file ids. Existing projection tables refresh only changed-file symbols plus one-hop reference/inheritance and pending-prune neighbors; missing projection tables return `full_required` so `UMonolithSourceSubsystem` can still health-gate through `RepairCrgCache(true)` as the bootstrap/fallback path. `Saved\graph.db` is not touched by routine source reindex completion.

### Reindex failure and completion contract

Source indexing is fail-closed for the observable run-boundary failures covered by this slice. Database open/reset/schema/prune failures, failed module/file/symbol row insertion, transaction begin/commit failures, final SQLite maintenance failure, and cancellation all produce an unsuccessful run. Scope-exit cleanup closes the writer before it clears the running flag and broadcasts completion exactly once with an explicit success outcome. Individual source-file parse limitations remain nonfatal and are reported through the existing diagnostics/statistics path. The legacy `void` include/source-chunk/inheritance/reference/deprecation/meta helpers do not expose individual statement status, so this contract does not claim per-row failure propagation for those helpers.

Plugin source discovery preserves the existing engine/project source corpus: every standalone directory named `Source` remains eligible even when it has no adjacent `.uplugin` descriptor (legacy modules and plugin templates are valid lookup inputs). A non-descriptor `Source` nested below another `Source` root is not registered as a second module because the enclosing root already covers its files; a genuinely nested plugin with an adjacent descriptor remains eligible and is ordered most-specific first. Every file then claims one normalized absolute identity per indexer instance (case-folded on Windows), preventing overlapping roots and case/relative spellings from inserting duplicate file content or symbols without dropping unique indexed paths. This is lexical path identity, not junction or hardlink identity. Stored module/file paths retain canonical on-disk casing for local roots; configured local roots are corrected once without resolving junctions, so incremental Windows runs remain stable across drive-letter/caller casing changes. UNC roots bypass UE 5.8's non-network-safe case-correction helper and retain their normalized `//` prefix and caller casing. `Monolith.IndexGuard.Source.PluginDescriptorDiscoveryDeduplicatesNestedSourceDirs` pins nested false-`Source` suppression, descriptor-free root retention, nested descriptor ownership, clean and case/relative-spelling incremental counts, and the duplicate-symbol boundary.

The editor subsystem keeps `GetDatabase()` unavailable while indexing, after a failed run, and during shutdown. A failed completion clears the in-flight state but leaves the DB closed and latched until a successful reindex; it does not reopen a partially written DB or rebuild CRG. A successful index completion reopens the DB while query access is still gated, attempts the CRG cache refresh, and then makes the DB queryable. A non-`ok` CRG refresh remains a warning that `source.health` can expose; it does not relatch an otherwise successful index run as failed. Thread-creation failure also clears the in-flight state without waiting for a callback.

`MonolithReindex` returns exit code `1` when synchronous execution fails, completion is missing, or completion reports failure; the mere presence of an old DB file is never success evidence. `Monolith.IndexGuard.Source.IndexerFatalPruneCompletesExactlyOnce`, `Monolith.IndexGuard.Source.IndexerCancellationReportsFailure`, and `Monolith.IndexGuard.Source.ReindexCommandletFatalIndexerExitCode` pin the prune cleanup/completion, cancellation-reporting, and commandlet failure-propagation slices of this contract.

**DB Location:** `Plugins/Monolith/Saved/EngineSource.db`

**Journal Mode:** `EngineSource.db` uses rollback-journal `DELETE`. Source writers set `PRAGMA journal_mode=DELETE`, `PRAGMA synchronous=NORMAL`, `PRAGMA locking_mode=NORMAL`, and `PRAGMA busy_timeout=5000`. Source and bridge read-only paths do not run `PRAGMA journal_mode=...`; they observe the current mode with `query_only=ON`. `EngineSource.db` WAL is not enabled because UE 5.7 `SQLiteCore` uses a custom `SQLITE_OS_OTHER` VFS without the shared-memory hooks required by WAL.

**Console Snapshot Tables:** `console_objects`, `console_objects_fts`, and `console_snapshot_meta` live in `EngineSource.db` because the console registry is source/runtime metadata rather than asset content. `MonolithConsole.refresh_snapshot` populates these tables from the live `IConsoleManager` registry; `MonolithConsole.search_objects`, `MonolithConsole.get_object`, and offline `monolith_query.exe console search_objects/get_object/health` read the captured snapshot. `console.search_objects` keeps payloads bounded with a 500-row compact cap and a 200-row full/detail cap, and emits search rows only under `results` to avoid duplicate payload arrays. `MonolithSourceSchema.h` remains the schema authority for these tables, but `MonolithSource` does not register the `console` namespace.

**Derived CRG Projection Cache:** `crg_nodes`, `crg_edges`, `crg_node_metrics`, `crg_meta`, `crg_snapshots`.
These tables are rebuildable projections over `symbols`, `"references"`, and
`inheritance`, not source-of-truth tables. `source.repair_crg_cache execute=true`
first checks `freshness_checks` and `repair_needed`; if the projection is already
current it returns `skipped=true` instead of rebuilding. When repair is needed it
purges stale/orphan metrics, recreates the projection, and `source.risk_score` reads `crg_node_metrics` first
before falling back to query-time scoring. Rebuilt projection metrics use
`crg_meta.scoring_version=3` for the token-boundary/camel-case aware UE-domain sensitivity factor; override fan-out
and overridden-parent counts are derived query-time from `symbols` + `inheritance`
and augment cached risk rows when present. `crg_snapshots`
is a derived review aid created only by `source.snapshot execute=true`; it stores
compact node/edge manifests and may be dropped/recreated without losing source data.
Project-only source reindexing keeps the same source-of-truth boundary: before re-inserting project rows it deletes only the existing project `files` slice and dependent rows, including stale `crg_*` projection rows. The prune stage also removes orphan symbol rows whose `file_id` no longer resolves to `files.id`, plus their dependent references, inheritance, includes, override edges, and projection rows. A temp table snapshots every reference row selected by pruned `file_id` or endpoint before source deletion; the same native ids delete derived `crg_edges`, and their surviving endpoint ids join the pending refresh set. It also keeps pruned symbols and surviving CRG/override neighbors in that set. After reinsertion, `RefreshCrgCacheForFiles` rebuilds scoped `crg_nodes`, `crg_edges`, `crg_node_metrics`, and `source_override_edges` for changed files plus one-hop/pending neighbors. `InsertModule` and `InsertFile` always return the canonical row id selected by their unique key after `INSERT OR IGNORE`, so duplicate project paths cannot accidentally attach new symbols to a stale `last_insert_rowid()`. The subsystem-level `RepairCrgCache(true)` remains the missing-table or stale-health fallback and skips when parity is already current.

**CRG-Compatible `Saved\graph.db`:** This is a separate graph-node search/export artifact, not the source of truth for `risk_score`, `review_context`, or `find_overrides`. Routine source work should use `source.search_source`, `source.risk_score`, `source.review_context`, `source.impact_radius`, `source.find_overrides`, and `source.health`; run `source.build_crg_graph --execute` only when the `Saved\graph.db` node/edge export or `source.search_crg_graph` surface is explicitly needed. The graph builder records `source_files`, `source_symbols`, `source_valid_references`, `source_inheritance`, `source_signature_version`, and `source_signature` in metadata so unchanged source input can skip the rebuild. The `flows`, `flow_memberships`, `flow_snapshots`, `communities`, `community_summaries`, and `risk_index` tables are reserved/unimplemented placeholders in the current graph schema and are excluded from health criteria.

### CRG-Inspired Navigation + Projection Cache — IMPLEMENTED (P0, 2026-05-16; cache 2026-05-17)

actions (`impact_radius`, `health`, `repair_fts`, `repair_crg_cache`, `risk_score`,

There is no Python runtime or generic parser replacement (monolith-native:
source-symbol, lexical/local).

**`find_overrides` list-projection contract (additive, 2026-07-04).** Optional `offset`
(or `cursor` from a prior `next_cursor`, which takes precedence and reuses the Core
`FMonolithProjectionUtils::ReadCursorOffset` numeric-cursor convention)
pages the `overrides` window over the BFS emission order (stable while the index is
unchanged) and optional `fields` (array or comma-separated) projects each override row to
`id`/`name`/`qualified_name`/`kind`/`file`/`path_status`/`line`/`depth`, warning on unknown
names. The response adds `total`, `returned`, `next_cursor` (the next offset, emitted while
more rows remain — including when the fetch window itself truncated the traversal), and a
`projection` echo next to the legacy fields. `total` counts the rows emitted by the current
fetch window (`offset + max_results`), not the full population — absence of `next_cursor`
is the completion signal. The traversal cannot page past the 2000-row
emission cap and warns when the cap is reached. The offline
`monolith_query.exe source find_overrides` mirrors the contract with `--offset`/`--cursor`/`--fields`,
a 1000-row cap, and canonical `line` plus additive `line_start`/`line_end`/`signature` row keys.
**Symbol-not-found is a real error envelope.** `risk_score`, `review_context`, and
`impact_radius` report a missing symbol in the result body as `status:"error"` with a
`"Symbol not found: <sym>"` summary; the handlers promote that body status to a real
action error (`isError=true`, code `-32602`) via `WrapReviewResult`, preserving the body
as `error.data` and attaching a `source.search_source` recovery hint/related action, so a
caller checking only the transport-level `isError` flag cannot mistake a not-found for a
successful empty answer. Bodies with `status` `ok`/`warning`/`stale` (degraded-but-has-data)

Invariants honored by the implementation:

- `EngineSource.db` is **Schema v3**; native `MonolithSourceSchema.h` (`SchemaVersion=3`, `meta.schema_version`) is the sole authority. The schema now includes source-symbol tables, CRG projection/cache tables, Reflection Intelligence tables, and `console_objects` snapshot tables. The legacy Python tree-sitter indexer is not a schema authority.
- `symbols_fts` is external-content (`content=symbols`) → supports `'rebuild'`. `source_fts` is a plain `fts5(file_id UNINDEXED, line_number UNINDEXED, text)` with no backing table → `'rebuild'` is meaningless; `source.repair_fts(target=source)` always degrades to a reindex recommendation. Triggers are `symbols_ai`/`symbols_ad` only (no `symbols_au`, no `source_fts` trigger) — `source.health` must expect exactly that set. `source.health` `next_actions` are reserved for required follow-up; optional deep diagnostics live under `maintenance_recommendation.optional_diagnostic_actions`.
- `"references"` is a quoted SQLite reserved word in schema and every query; new traversal/fixtures must quote it. Traversal: calls/type refs `from_symbol_id → to_symbol_id` (`GetReferencesTo`/`GetReferencesFrom`), inheritance `child_id → parent_id`, and function override edges `child method → parent method`. `call`, `type`, and `override` edge filters are exact; `includes` is file/path-level (no `included_file_id`) and returns a P0 warning until path→`files.path` resolution exists.
- Override edges are derived, not source-of-truth rows. `source.repair_crg_cache execute=true` materializes signature-aware override pairs into `source_override_edges` (`source_override_edges_version=2`) so `source.find_overrides`, `impact_radius(edge_kinds=...|override)`, `risk_score`, `review_context`, and `review_hotspots kind=override` can use indexed lookups. Use `scope=override_edges` for the fast cache-only refresh path when CRG node/edge/metric parity does not need a full rebuild. If that cache is missing or stale, the read actions fall back to query-time derivation. Both paths join child classes to all ancestor classes through `symbols.parent_symbol_id` + transitive `inheritance`, handle implementation-only qualified names such as `AActor::BeginPlay`, require exact method-name parity, and require matching normalized parameter lists so overloads with different signatures are not treated as overrides. If a signature is missing or unparsable, the edge is preserved with medium confidence instead of being silently dropped. Qualified symbols such as `UMyBase::Tick` should be used when a function name is repeated across classes.
- `FMonolithSourceDatabase` is a **read/write** wrapper with a private `DbLock`; `source.repair_fts` and `source.repair_crg_cache` writes must run inside DB/helper methods that can take the private lock, gated on `UMonolithSourceSubsystem::IsIndexing()`. Write-capable opens own `EngineSource.db` rollback-journal setup; read-only source and bridge callers must never change journal mode.
- CRG projection rows are disposable: `crg_nodes` maps one row per symbol, `crg_edges` maps one row per valid reference/inheritance edge, and `crg_node_metrics` stores `risk_score`, tier, reasons JSON, raw count JSON, and `scoring_version`. Missing projection rows are cache misses, not action failures; current scoring is v3 and includes a bounded UE-domain sensitivity signal matched on token boundaries and camel-case segments rather than arbitrary substrings. Query-time `risk_score` augments both cache hits and misses with `override_children` and `overridden_parents`.
- Project-only source reindexing must not append a second copy of every project symbol or force a full CRG rebuild after every source edit. `FMonolithSourceDatabase::PruneIndexedFilesUnderRoots` removes existing project-root file rows and all dependent source/projection rows before the indexer loads existing engine symbols and indexes the project modules. It snapshots doomed native reference ids before deleting the source rows, removes the matching derived CRG edges even when both endpoint symbols survive, and schedules those surviving endpoints for metric refresh. It also prunes any orphan source symbols left behind by a prior conflicting file path insert, preventing references/inheritance/CRG edges from pointing at nonexistent file rows. `InsertModule` and `InsertFile` re-select the canonical module/file id after `INSERT OR IGNORE`, avoiding stale `last_insert_rowid()` reuse on unique-key conflicts. `FMonolithSourceDatabase::RefreshCrgCacheForFiles` then refreshes changed-file symbols plus one-hop reference/inheritance neighbors and pending prune neighbors, rebuilds `source_override_edges`, and clears the pending set after commit. `Monolith.IndexGuard.Source.PruneIndexedFilesUnderRootsRemovesProjectSlice` covers engine-symbol preservation, project-symbol removal, orphan cleanup, file-owned and endpoint-owned reference/projection cleanup, canonical-id duplicate reinsertion, scoped source CRG parity, and old-neighbor risk metric recomputation.
- `source.detect_changes` is read-only changed-path review triage over `files`, `symbols`, quoted `"references"`, and the cached/query-time risk path. It escapes SQL `LIKE` wildcards in changed path suffixes so `_` and `%` match literal source filenames rather than broad patterns. It exposes `input` (including `precision` ∈ `{file,line}` and `range_paths`), `limits`, `risk_score`, `scoring_version`, top-level `changed_entity_count` / `impacted_count` / `test_gap_count` in every detail level, standard-mode `changed_entities[]` (with `matched_ranges` under line precision), `impact`, heuristic `test_gaps[]`, `review_priorities`, `truncated`, and `next_actions`; it is VCS-agnostic and must not shell out to P4/git. RX-1.1 line precision (port of CRG `changes.py:_parse_unified_diff` + the `line_start<=end AND line_end>=start` overlap rule) is additive and opt-in: callers pass `changed_ranges` and/or a unified-diff `diff_text` (the plugin parses the text only — the caller produces the diff). `FMonolithSourceDatabase::ParseUnifiedDiffRanges` is the shared public parser; a path that appears only in `changed_ranges`/`diff_text` is still treated as a changed path; malformed ranges and non-positive line spans degrade safely to file-level. `pre_merge_check` stays file-level (passes no ranges). This Monolith spec is authoritative for the ported behavior.
- `source.pre_merge_check` is a read-only pre-merge gate over `health`, `detect_changes`, and optional `find_unused`. It exposes `decision` (`pass`/`warn`/`fail`), `checks[]`, `findings[]`, `risk_score`, `truncated`, and standard-mode nested `health` / `change_analysis` / `unused` payloads. It is advisory, does not mutate, and does not shell out to P4/git.
- `source.snapshot` is dry-run by default and writes only when `execute=true`. It creates/updates derived `crg_snapshots` rows from the current CRG projection manifest and never rebuilds the projection itself. Auto labels use high-resolution UTC ticks to avoid same-second overwrite collisions.
- `source.diff_snapshots` is read-only and compares a stored snapshot against another stored snapshot or the current projection. It accepts positional refs and `--before`/`--after` refs, including mixed `--before=<ref> <after-ref>` calls. It exposes `summary`, capped `new_nodes[]`, `removed_nodes[]`, `new_edges[]`, `removed_edges[]`, `truncated`, and `next_actions`; if the current CRG projection cannot be queried, it returns `status=error` rather than diffing against an empty manifest.
- `source.review_hotspots` is read-only global triage over cached/native fan, risk, LOC, and override signals. `kind=override` ranks virtual/override contracts by signature-aware child overrides and overridden parents, using `source_override_edges` when available. It exposes `input`, `limits`, `hotspots[]`, optional `questions[]`, `truncated`, and `next_actions`, and intentionally avoids community/betweenness semantics.
- `source.find_unused` is read-only advisory dead-symbol discovery over `symbols`, quoted `"references"`, and `inheritance`. It exposes `input`, `limits`, capped `items[]`, `confidence`, `reasons[]`, `truncated`, and `next_actions`; it must be recall-first (`min_confidence=low`) by default because UE reflection, delegates, Blueprint references, and soft-path references are outside the graph.
- `source.review_context` is a dedicated CRG-style review package distinct from single-item `bridge.build_attachment`; it exposes `input`, `limits`, `risk`, `top_risks[]`, `impact`, compact `context[]`, `truncated`, and `next_actions`. Seed and context rows include `path_status=known|missing`, seed lookup prefers known paths over missing-path duplicates, and top impacted rows keep the known-path variant when the same qualified/kind/file identity also appears as missing. Its impact summary includes override edges by default through `call|type|inheritance|override`.
- `source.build_crg_graph` builds a CRG-compatible `Saved\graph.db` natively from `Saved\EngineSource.db` files, symbols, `"references"`, and `inheritance`; it does not import code from or depend on `D:\P4\CRG`. Execute builds are single-flight via `graph.db.rebuild.lock`, build into `graph.db.rebuild.<pid>.tmp`, validate `nodes > 0`, `edges > 0`, `nodes == nodes_fts`, and `metadata.schema_version=9`, then atomically replace the old graph. Existing graph readers should continue to see the old graph during the build. Live editor/MCP execute calls return immediately with `status=started`, `job_id`, and `poll_action=source.crg_graph_health`; offline `monolith_query.exe source build_crg_graph --execute` remains synchronous for scripts. `source.search_crg_graph` reads the graph through `nodes_fts` first and falls back to LIKE search only when FTS has no results, exposes `path_status`, and applies known-path-first duplicate suppression; graph-open lock failures degrade to structured busy/warning JSON with `source.search_source`, `source.risk_score`, and `source.review_context` as fallback actions.
- `bridge.search_asset_symbols` is the RX-6 cross-DB bridge. It remains read-only in editor and offline CLI paths: it never writes ProjectIndex, EngineSource, CRG cache, graph DB, or snapshots; it never shells out to P4/git; and it must degrade with `warnings[]` when either index is unavailable or currently indexing. The bridge requires exactly one non-empty string seed (`asset_path` or `symbol`) and rejects wrong-typed seeds with `-32602` instead of silently selecting the other mode. The bridge is heuristic rather than authoritative: asset-seeded lookups derive candidate native class names from the package path, asset name, asset class, and common UE prefixes/suffixes, then search EngineSource symbols with bounded exact-name/FTS queries before score-sorting and trimming; symbol-seeded lookups search source symbols first and then ProjectIndex assets by exact/normalized names, evaluating the bounded symbol set before global score sorting rather than stopping on a pre-ranking candidate cap. Duplicate asset/symbol pairs preserve the highest-scoring candidate so an early lexical hit cannot block a later exact/normalized hit. Every returned item must include `confidence` (`high|medium|low`) plus concrete `reasons[]` so reviewers can tell whether a match came from exact name parity, normalized prefix stripping, asset class hints, or lexical fallback, and `truncated=true` when more than `limit` scored links are available. Offline parity uses `monolith_query bridge search_asset_symbols` over `ProjectIndex.db` and `EngineSource.db`, with the same `links[]`, `warnings[]`, `count`, `truncated`, and `lexical_only=true` output shape.
