## MonolithSource

**Dependencies:** Core, CoreUObject, Engine, MonolithCore, MonolithIndex, SQLiteCore, EditorSubsystem, UnrealEd, Json, JsonUtilities, Slate, SlateCore

**Note:** Module structure was flattened — the vestigial outer stub has been removed. MonolithSource registers the `source` and `bridge` surfaces described below. The engine source indexer is a native C++ implementation (`UMonolithSourceSubsystem` builds `EngineSource.db` in-process). The legacy Python tree-sitter indexer (`Scripts/source_indexer/`) is no longer used and is not a schema authority. `MonolithSourceSchema.h` remains the native aggregate EngineSource schema/migration authority; portable symbol/source FTS SQL lives in `MonolithSourceSymbolSearchSchema.h`, portable graph-node VIEW/FTS SQL lives in `MonolithSourceGraphSearchSchema.h`, and portable console snapshot SQL lives in `MonolithSourceConsoleSchema.h`. These public SQL contracts are consumed by MonolithSource and standalone Query so live migration and offline repair cannot drift.

### Auto-Reindex on Hot-Reload (F17)

**Important:** `monolith_reindex` is the **asset/project** indexer (Blueprints, materials, textures via `MonolithIndex`). It does NOT update the C++ source DB. Source-symbol freshness is owned by this module via:

1. `source.trigger_reindex` — full clean rebuild (engine + shaders + project).
2. `source.trigger_project_reindex` — incremental, project C++ only. Before indexing project `Source` and project-plugin `Source` roots, the indexer prunes existing indexed files under those roots plus dependent `symbols`, `"references"`, `inheritance`, `includes`, source FTS rows, `source_override_edges`, and matching `crg_*` projection rows. Reference ids are snapshotted before deletion, so a reference row owned by a pruned file removes its derived CRG edge even when both endpoint symbols are retained; both surviving endpoints enter the temporary pending set so completion refresh recomputes their metrics. The same pending set retains affected old-neighbor symbol ids for references removed with pruned symbols. This prevents duplicate project symbols or stale native-reference CRG edges from accumulating while preserving engine/shader rows for cross-reference resolution. Offline `monolith_query.exe source trigger_project_reindex` is a DB-free live-only guidance action and does not mutate `EngineSource.db`.
3. **F17 auto-hook (2026-04-26):** while durable indexing activation is on, `UMonolithSourceSubsystem` listens on `FCoreUObjectDelegates::ReloadCompleteDelegate`. After every Live Coding patch and after every UBT-driven editor restart that fires hot-reload, the subsystem auto-kicks `TriggerProjectReindex()` (async). Guarded by a 5-second cooldown and an in-flight `bIsIndexing` flag so multi-module reload bursts don't storm.

With activation enabled, agents do not need to invoke a source-reindex action manually in the common dev loop — startup selects a project-only catch-up for an existing DB or full bootstrap for a missing DB, then UBT/Live Coding refreshes project symbols through F17. With activation disabled, the delegate is absent and all direct reindex actions reject the request, but existing `EngineSource.db` reads remain available. On project source indexing completion, `FMonolithSourceIndexer` calls `FMonolithSourceDatabase::RefreshCrgCacheForFiles` for the newly indexed file ids. Existing projection tables refresh changed-file symbols plus one-hop reference/inheritance and pending-prune neighbors. Reference selection also includes every row whose `references.file_id` belongs to a newly indexed file, even when both resolved endpoint symbols are retained engine symbols; both endpoints enter the metric refresh set. This keeps CRG edge and risk-metric parity with the native reference table for references whose ownership file differs from their resolved symbol ownership. If an existing native source DB predates the CRG projection tables, the indexer performs one explicit full projection bootstrap instead; this also applies when the project slice is empty, so a successful run never leaves the derived schema absent. The scoped refresh or required bootstrap is part of the project-index success boundary: a non-`ok` result fails the index run explicitly, and the editor subsystem does not hide it with a redundant full cache rebuild. Full clean source indexing still performs one full CRG rebuild after reopening the regenerated database. The same EngineSource write lifecycle keeps `source_graph_nodes_fts` synchronized with the authoritative `files` and `symbols` rows; there is no separate graph export to refresh.

### Durable indexing activation

The shared local state lives at `Saved/Monolith/Activation.ini`; a missing file/key defaults `IndexingEnabled` to true, while a malformed value fails closed to false. `Monolith.StartIndexing` persists true, then enables both `UMonolithSourceSubsystem` and `UMonolithIndexSubsystem` and starts each subsystem's cheapest correct catch-up. `Monolith.StopIndexing` persists false and unbinds the source reload delegate plus asset delegates/timers. An active writer drains to its established completion boundary because cancelling source after it has closed the read handle, or cancelling an asset full-reset between schema phases, could leave a deliberately unavailable DB.

Activation controls writers only. Source subsystem initialization attempts to open `EngineSource.db` before consulting activation, and `GetDatabase()` remains available for reads whenever the DB is healthy and no writer owns it. `bridge.get_index_status` exposes `indexing_activation_enabled`; `bridge.start_indexing`, `source.trigger_reindex`, and `source.trigger_project_reindex` require true and never mutate it.

The `MonolithReindex` commandlet also fails closed while activation is off. `-AllowWhenIndexingDisabled` is an explicit one-shot maintenance/test override that does not change the durable state; normal post-build and watchdog paths do not pass it unless their own documented force override is explicitly selected.

### Reindex failure and completion contract

Source indexing is fail-closed for the observable run-boundary failures covered by this slice. Database open/reset/schema/prune failures, failed module/file/symbol row insertion, transaction begin/commit failures, final SQLite maintenance failure, project-index scoped CRG refresh failure, and cancellation all produce an unsuccessful run. Scope-exit cleanup closes the writer before it clears the running flag and broadcasts completion exactly once with an explicit success outcome. Individual source-file parse limitations remain nonfatal and are reported through the existing diagnostics/statistics path. The legacy `void` include/source-chunk/inheritance/reference/deprecation/meta helpers do not expose individual statement status, so this contract does not claim per-row failure propagation for those helpers.

Plugin source discovery preserves the existing engine/project source corpus: every standalone directory named `Source` remains eligible even when it has no adjacent `.uplugin` descriptor (legacy modules and plugin templates are valid lookup inputs). A non-descriptor `Source` nested below another `Source` root is not registered as a second module because the enclosing root already covers its files; a genuinely nested plugin with an adjacent descriptor remains eligible and is ordered most-specific first. Every file then claims one normalized absolute identity per indexer instance (case-folded on Windows), preventing overlapping roots and case/relative spellings from inserting duplicate file content or symbols without dropping unique indexed paths. This is lexical path identity, not junction or hardlink identity. Stored module/file paths retain canonical on-disk casing for local roots; configured local roots are corrected once without resolving junctions, so incremental Windows runs remain stable across drive-letter/caller casing changes. UNC roots bypass UE 5.8's non-network-safe case-correction helper and retain their normalized `//` prefix and caller casing. `Monolith.IndexGuard.Source.PluginDescriptorDiscoveryDeduplicatesNestedSourceDirs` pins nested false-`Source` suppression, descriptor-free root retention, nested descriptor ownership, clean and case/relative-spelling incremental counts, and the duplicate-symbol boundary.

The editor subsystem keeps `GetDatabase()` unavailable while indexing, after a failed run, and during shutdown. A failed completion clears the in-flight state but leaves the DB closed and latched until a successful reindex; it does not reopen a partially written DB or rebuild CRG. A successful full index completion reopens the DB while query access is still gated, performs one full CRG cache rebuild, and then makes the DB queryable. A successful project index completion reopens the DB and retains the indexer's already verified scoped CRG refresh instead of repeating an expensive full rebuild. Thread-creation failure also clears the in-flight state without waiting for a callback.

`MonolithReindex` returns exit code `1` when synchronous execution fails, completion is missing, or completion reports failure; the mere presence of an old DB file is never success evidence. `Monolith.IndexGuard.Source.IndexerFatalPruneCompletesExactlyOnce`, `Monolith.IndexGuard.Source.IndexerCancellationReportsFailure`, and `Monolith.IndexGuard.Source.ReindexCommandletFatalIndexerExitCode` pin the prune cleanup/completion, cancellation-reporting, and commandlet failure-propagation slices of this contract. `Monolith.IndexGuard.Source.PruneIndexedFilesUnderRootsRemovesProjectSlice` additionally pins the surviving-endpoint/file-owned reference case through scoped refresh, CRG edge parity, and refreshed fan-out metrics.

**DB Location:** `Plugins/Monolith/Saved/EngineSource.db`. Standalone Query resolves
its default `Saved` directory from the nearest executable-ancestor containing
`Monolith.uplugin`, so both the fixed `Binaries/monolith_query.exe` compatibility
entry point and manifest-selected immutable binaries stay inside the owning
Monolith checkout even when a broader sibling such as `Plugins/Saved` exists.
Explicit `--db`, `--source-db`, and `--project-db` overrides still take precedence.

**Journal Mode:** `EngineSource.db` uses rollback-journal `DELETE`. Source writers set `PRAGMA journal_mode=DELETE`, `PRAGMA synchronous=NORMAL`, `PRAGMA locking_mode=NORMAL`, and `PRAGMA busy_timeout=5000`. Source and bridge read-only paths do not run `PRAGMA journal_mode=...`; they observe the current mode with `query_only=ON`. `EngineSource.db` WAL is not enabled because UE 5.7 `SQLiteCore` uses a custom `SQLITE_OS_OTHER` VFS without the shared-memory hooks required by WAL.

**Console Snapshot Tables:** `console_objects`, `console_objects_fts`, and `console_snapshot_meta` live in `EngineSource.db` because the console registry is source/runtime metadata rather than asset content. `MonolithConsole.refresh_snapshot` populates these tables from the live `IConsoleManager` registry; `MonolithConsole.search_objects`, `MonolithConsole.get_object`, and offline `monolith_query.exe console search_objects/get_object/health` read the captured snapshot. `console.search_objects` keeps payloads bounded with a 500-row compact cap and a 200-row full/detail cap, and emits search rows only under `results` to avoid duplicate payload arrays. The portable public `MonolithSourceConsoleSchema.h` is the SQL authority shared by Unreal and standalone Query; private `MonolithSourceSchema.h` only adapts those UTF-8 literals to SQLiteCore's TCHAR interface. `MonolithSource` does not register the `console` namespace.

**Derived CRG Projection Cache:** `crg_nodes`, `crg_edges`, `crg_node_metrics`, `crg_meta`, `crg_snapshots`.
These tables are rebuildable projections over `symbols`, `"references"`, and
`inheritance`, not source-of-truth tables. If a derived-table count reports SQLite
corruption while the native tables remain readable, repair transactionally drops and
recreates only the CRG projection schema before repopulating it; it never substitutes
or discards the authoritative native index. `source.repair_crg_cache execute=true`
first checks `freshness_checks` and `repair_needed`; if the projection is already
current it returns `skipped=true` instead of rebuilding. When repair is needed it
purges stale/orphan metrics, recreates the projection, and `source.risk_score` reads `crg_node_metrics` first
before falling back to query-time scoring. Rebuilt projection metrics use
`crg_meta.scoring_version=3` for the token-boundary/camel-case aware UE-domain sensitivity factor; override fan-out
and overridden-parent counts are derived query-time from `symbols` + `inheritance`
and augment cached risk rows when present. `crg_snapshots`
is a derived review aid created only by `source.snapshot execute=true`; it stores
compact node/edge manifests and may be dropped/recreated without losing source data.
Project-only source reindexing keeps the same source-of-truth boundary: before re-inserting project rows it deletes only the existing project `files` slice and dependent rows, including stale `crg_*` projection rows. The prune stage also removes orphan symbol rows whose `file_id` no longer resolves to `files.id`, plus their dependent references, inheritance, includes, override edges, and projection rows. A temp table snapshots every reference row selected by pruned `file_id` or endpoint before source deletion; the same native ids delete derived `crg_edges`, and their surviving endpoint ids join the pending refresh set. It also keeps pruned symbols and surviving CRG/override neighbors in that set. After reinsertion, `RefreshCrgCacheForFiles` rebuilds scoped `crg_nodes`, `crg_edges`, `crg_node_metrics`, and `source_override_edges` for changed files plus one-hop/pending neighbors. If those projection tables are absent, the indexer owns a single full `RepairCrgCache(true)` bootstrap before it reports success. `InsertModule` and `InsertFile` always return the canonical row id selected by their unique key after `INSERT OR IGNORE`, so duplicate project paths cannot accidentally attach new symbols to a stale `last_insert_rowid()`.

**EngineSource graph-node search projection:** `source_graph_nodes` is the canonical VIEW over authoritative `files` and `symbols`. It presents the former graph-node row shape without duplicating data: File rows use negative file ids and `kind=File`; symbol rows keep symbol ids and normalize class/struct/interface to `Class`, function/method/constructor/destructor to `Function` (or `Test` for test paths), enum/typedef/type/delegate to `Type`, and preserve other kinds. The VIEW provides `id`, `kind`, `name`, `qualified_name`, `file_path`, `line_start`, `line_end`, `language`, and `signature`. `source_graph_nodes_fts` is an external-content FTS5 table over `name`, `qualified_name`, `file_path`, and `signature`, with `content=source_graph_nodes`, `content_rowid=id`, and `tokenize='porter unicode61'`. File/symbol insert, update, and delete triggers maintain FTS incrementally. On editor startup, `FMonolithSourceDatabase::Open` runs `CreateTablesIfNeededLocked` after opening/configuring the existing DB and before returning it; an incomplete or unstamped Schema v3 graph-search slice is upgraded to v4 by one idempotent transaction that creates the VIEW/FTS/triggers, rebuilds and integrity-checks when required, then records both `meta.source_graph_nodes_fts_version` and `meta.schema_version`. Migration failure rolls back, closes the DB, and leaves the subsystem unavailable rather than exposing a partially migrated index.

`source.search_crg_graph` is the only retained graph-node action. Live MCP requires `query`; before delegating, its handler requires the editor subsystem, rejects an in-progress source index, and calls `GetDatabase()` as the readiness gate. It then passes the subsystem's authoritative `GetDatabasePath()` to the standalone Query process as `--source-db`, preventing executable-location or working-directory defaults from selecting a different DB. The direct offline CLI also accepts a positional query, `--query`, or `--q`. Both surfaces accept optional case-insensitive exact `kind` and a clamped `limit` of 1..200. The canonical Query implementation escapes the query into prefix-token AND FTS syntax and asks FTS5 for a rank-ordered rowid pool before resolving those ids through the canonical VIEW; joining the complete broad MATCH set to the UNION-backed VIEW is forbidden because it materializes and sorts millions of rows. The initial candidate bound is `max(4096, 64 * (limit + 1))`. A `limit + 1` sentinel and the first omitted BM25 rank prove whether the pool contains the observable known-path/kind boundary; an equal-rank omitted row is not considered proven because the legacy kind/qualified-name/id tie-break can still change the result. An unproven pool doubles geometrically up to 65,536 candidates, then uses the former unbounded SQL only as the final correctness fallback. The response exposes the initial/final bound, expansion count, candidate count, pool truncation, and full-fallback state under `limits`. Candidate ids are database-owned signed 64-bit integers embedded as numeric literals, avoiding SQLite bind-count limits while keeping the query injection-safe; the optional `kind` remains a bound, case-insensitive exact SQL filter. C++ then reproduces the frozen known-path, native-double BM25, kind, qualified-name, and id ordering exactly. The previous LIKE ranking runs only after the FTS statement prepared and stepped successfully but returned zero rows. FTS prepare/step failure is not a zero-hit: it returns `status=warning`, empty `results`, `used_fts=false`, and an actionable entry in `warnings`/`next_actions`, without running LIKE. Successful searches fetch `limit+1` and report `truncated` before stable identity de-duplication. De-duplication first removes exact `qualified_name|kind|file_path` repeats, then suppresses only missing-path variants whose numeric storage suffix-stripped qualified name, kind, name, and signature match an already ranked known-path row; this preserves overloads and distinct known-path definitions while keeping the trusted row. Each result keeps `id`, `kind`, `name`, `qualified_name`, shortened `file_path`, `path_status`, line range, language, signature, and score. Root fields are `backend` (`engine_source_fts`), `input`, `limits`, `results`, `warnings`, `status`, `summary`, `count`, `used_fts`, `truncated`, and `next_actions`. Missing VIEW/FTS similarly returns a structured warning with `source.health`, graph-node FTS repair, and reindex guidance.

The separate `build_crg_graph`, `rebuild_crg_graph`, `repair_crg_graph`, and `crg_graph_health` actions and every `graph_db`/`--graph-db` argument are removed. Standalone Query normalizes CLI option names and rejects `--graph-db` globally, for every namespace/action, before catalog validation, path resolution, or any database open; callers must use `--source-db` or `--db` for an EngineSource override. Graph-node availability and parity are part of `source.health`: shallow `fts:graph_nodes_view`, `fts:graph_nodes_table`, and `fts:graph_nodes_readiness` checks validate the objects/trigger/version contract plus bounded MATCH+rowid access to a negative File id and positive Symbol id when present; deep `fts:graph_nodes_row_parity` compares the complete VIEW row count with the index-owned `source_graph_nodes_fts_docsize` row manifest. Any missing object, failed readiness probe, version mismatch, or deep parity mismatch recommends `source.repair_fts target=graph_nodes execute=true`. The offline Query repair and live DB helper consume the same portable schema SQL: they recreate the canonical VIEW/FTS/nine triggers, rebuild, integrity-check, and write the FTS/schema markers in one transaction, including when the objects are missing. `risk_score`, `review_context`, `impact_radius`, `review_hotspots`, and `find_overrides` continue to use EngineSource native/`crg_*` data and are unaffected by removal of the export artifact.

Acceptance is intentionally concentrated on the retained high-ROI contract:

1. Opening an existing Schema v3 DB runs the v4 graph-search migration before the DB becomes available. The migration creates the VIEW, FTS table, nine-trigger set, rebuild/integrity result, and both version markers transactionally; failure rolls back and fails the open rather than exposing partial v4 state.
2. One compact golden fixture covers File and Symbol rows, every normalized kind family, signature-only FTS hits, known/missing-path priority, identity de-duplication, successful-zero-FTS LIKE fallback, limit clamping, and truncation. Broad-query fixtures cover a proven 4,096-row boundary and 4,100 equal-rank rows whose reverse qualified-name order forces one expansion to 8,192; both must match the former ordering without an unbounded fallback. A separate fault fixture proves FTS prepare/step failure returns a structured warning with empty results and never executes LIKE. Expected successful rows and ordering match the former `search_crg_graph` behavior except for `backend=engine_source_fts`, bounded-candidate diagnostics, and removal of graph-artifact fields.
3. Live MCP gates on `UMonolithSourceSubsystem` readiness/`IsIndexing()` and passes its authoritative EngineSource path through `--source-db`; direct offline CLI uses the same canonical Query implementation. The two surfaces produce the same result object for the same DB/query. Empty live input remains `-32602`; empty direct CLI input remains nonzero command usage failure.
4. Shallow health proves VIEW/FTS/trigger/version readiness and bounded FTS access to representative negative File and positive Symbol rowids. Deep/counted health proves `source_graph_nodes = files + symbols` and full `source_graph_nodes_fts_docsize = source_graph_nodes` parity on a copied database.
5. `repair_fts(target=graph_nodes)` and the graph-node slice of `target=all` recover missing VIEW/FTS/triggers, rebuild and integrity-check the index, and stamp FTS/Schema versions in one transaction; injected failure proves rollback. Full and project-only source indexing keep the same parity without an export job.
6. Catalog/help/dispatch tests prove the four retired graph maintenance names and graph-specific action parameters are absent. CLI tests prove normalized `graph_db` is rejected for every namespace/action before any DB open. Search, reindex, health, repair, watchdog, and release verification assert that no `Saved\graph.db`, rebuild lock, temp export, or graph-specific environment setting is opened or created; unrelated CRG review results remain regression-stable.

Invariants honored by the implementation:

- `EngineSource.db` is **Schema v4**; native `MonolithSourceSchema.h` (`SchemaVersion=4`, `meta.schema_version`) is the aggregate EngineSource authority, with symbol/source FTS SQL sourced from `MonolithSourceSymbolSearchSchema.h`, graph-search SQL sourced from `MonolithSourceGraphSearchSchema.h`, and console snapshot SQL sourced from `MonolithSourceConsoleSchema.h`; all three portable public headers are shared with Query. The schema includes source-symbol tables, CRG projection/cache tables, the canonical graph-node VIEW/FTS, Reflection Intelligence tables, and `console_objects` snapshot tables. The legacy Python tree-sitter indexer is not a schema authority. `FMonolithSourceDatabase::Open` must run the idempotent v3 -> v4 migration before returning an existing DB and must close/fail the open if that transaction cannot complete.
- `symbols_fts` is external-content (`content=symbols`) and `source_graph_nodes_fts` is external-content (`content=source_graph_nodes`) → both support `'rebuild'`. `source_fts` is a plain `fts5(file_id UNINDEXED, line_number UNINDEXED, text)` with no backing table → `'rebuild'` is meaningless; `source.repair_fts(target=source)` always degrades to a reindex recommendation. Symbol triggers remain `symbols_ai`/`symbols_ad`; graph-node FTS owns its nine file/symbol insert/update/delete triggers. A graph-node repair must recreate all canonical objects, rebuild, integrity-check, and stamp `source_graph_nodes_fts_version` plus `schema_version` atomically. Shallow health must probe negative File and positive Symbol rowids with bounded MATCH queries; deep health must compare the VIEW with `source_graph_nodes_fts_docsize`, not the external-content virtual-table count. `source.health` `next_actions` are reserved for required follow-up; optional deep diagnostics live under `maintenance_recommendation.optional_diagnostic_actions`.
- `"references"` is a quoted SQLite reserved word in schema and every query; new traversal/fixtures must quote it. Traversal: calls/type refs `from_symbol_id → to_symbol_id` (`GetReferencesTo`/`GetReferencesFrom`), inheritance `child_id → parent_id`, and function override edges `child method → parent method`. `call`, `type`, and `override` edge filters are exact; `includes` is file/path-level (no `included_file_id`) and returns a P0 warning until path→`files.path` resolution exists.
- Override edges are derived, not source-of-truth rows. `source.repair_crg_cache execute=true` materializes signature-aware override pairs into `source_override_edges` (`source_override_edges_version=2`) so `source.find_overrides`, `impact_radius(edge_kinds=...|override)`, `risk_score`, `review_context`, and `review_hotspots kind=override` can use indexed lookups. Use `scope=override_edges` for the fast cache-only refresh path when CRG node/edge/metric parity does not need a full rebuild. If that cache is missing or stale, the read actions fall back to query-time derivation. Both paths join child classes to all ancestor classes through `symbols.parent_symbol_id` + transitive `inheritance`, handle implementation-only qualified names such as `AActor::BeginPlay`, require exact method-name parity, and require matching normalized parameter lists so overloads with different signatures are not treated as overrides. If a signature is missing or unparsable, the edge is preserved with medium confidence instead of being silently dropped. Qualified symbols such as `UMyBase::Tick` should be used when a function name is repeated across classes.
- `FMonolithSourceDatabase` is a **read/write** wrapper with a private `DbLock`; `source.repair_fts` and `source.repair_crg_cache` writes must run inside DB/helper methods that can take the private lock, gated on `UMonolithSourceSubsystem::IsIndexing()`. Write-capable opens own `EngineSource.db` rollback-journal setup; read-only source and bridge callers must never change journal mode.
- CRG projection rows are disposable: `crg_nodes` maps one row per symbol, `crg_edges` maps one row per valid reference/inheritance edge, and `crg_node_metrics` stores `risk_score`, tier, reasons JSON, raw count JSON, and `scoring_version`. Missing projection rows are cache misses, not action failures; current scoring is v3 and includes a bounded UE-domain sensitivity signal matched on token boundaries and camel-case segments rather than arbitrary substrings. Query-time `risk_score` augments both cache hits and misses with `override_children` and `overridden_parents`.
- Project-only source reindexing must not append a second copy of every project symbol or force a full CRG rebuild after every source edit. `FMonolithSourceDatabase::PruneIndexedFilesUnderRoots` removes existing project-root file rows and all dependent source/projection rows before the indexer loads existing engine symbols and indexes the project modules. It snapshots doomed native reference ids before deleting the source rows, removes the matching derived CRG edges even when both endpoint symbols survive, and schedules those surviving endpoints for metric refresh. It also prunes any orphan source symbols left behind by a prior conflicting file path insert, preventing references/inheritance/CRG edges from pointing at nonexistent file rows. `InsertModule` and `InsertFile` re-select the canonical module/file id after `INSERT OR IGNORE`, avoiding stale `last_insert_rowid()` reuse on unique-key conflicts. `FMonolithSourceDatabase::RefreshCrgCacheForFiles` then refreshes changed-file symbols plus one-hop reference/inheritance neighbors and pending prune neighbors, rebuilds `source_override_edges`, and clears the pending set after commit. `Monolith.IndexGuard.Source.PruneIndexedFilesUnderRootsRemovesProjectSlice` covers engine-symbol preservation, project-symbol removal, orphan cleanup, file-owned and endpoint-owned reference/projection cleanup, canonical-id duplicate reinsertion, scoped source CRG parity, and old-neighbor risk metric recomputation.
- `source.detect_changes` is read-only changed-path review triage over `files`, `symbols`, quoted `"references"`, and the cached/query-time risk path. It escapes SQL `LIKE` wildcards in changed path suffixes so `_` and `%` match literal source filenames rather than broad patterns. It exposes `input` (including `precision` ∈ `{file,line}` and `range_paths`), `limits`, `risk_score`, `scoring_version`, top-level `changed_entity_count` / `impacted_count` / `test_gap_count` in every detail level, standard-mode `changed_entities[]` (with `matched_ranges` under line precision), `impact`, heuristic `test_gaps[]`, `review_priorities`, `truncated`, and `next_actions`; it is VCS-agnostic and must not shell out to P4/git. RX-1.1 line precision (port of CRG `changes.py:_parse_unified_diff` + the `line_start<=end AND line_end>=start` overlap rule) is additive and opt-in: callers pass `changed_ranges` and/or a unified-diff `diff_text` (the plugin parses the text only — the caller produces the diff). `FMonolithSourceDatabase::ParseUnifiedDiffRanges` is the shared public parser; a path that appears only in `changed_ranges`/`diff_text` is still treated as a changed path; malformed ranges and non-positive line spans degrade safely to file-level. `pre_merge_check` stays file-level (passes no ranges). This Monolith spec is authoritative for the ported behavior.
- `source.pre_merge_check` is a read-only pre-merge gate over `health`, `detect_changes`, and optional `find_unused`. It exposes `decision` (`pass`/`warn`/`fail`), `checks[]`, `findings[]`, `risk_score`, `truncated`, and standard-mode nested `health` / `change_analysis` / `unused` payloads. It is advisory, does not mutate, and does not shell out to P4/git.
- `source.snapshot` is dry-run by default and writes only when `execute=true`. It creates/updates derived `crg_snapshots` rows from the current CRG projection manifest and never rebuilds the projection itself. Auto labels use high-resolution UTC ticks to avoid same-second overwrite collisions.
- `source.diff_snapshots` is read-only and compares a stored snapshot against another stored snapshot or the current projection. It accepts positional refs and `--before`/`--after` refs, including mixed `--before=<ref> <after-ref>` calls. It exposes `summary`, capped `new_nodes[]`, `removed_nodes[]`, `new_edges[]`, `removed_edges[]`, `truncated`, and `next_actions`; if the current CRG projection cannot be queried, it returns `status=error` rather than diffing against an empty manifest.
- `source.review_hotspots` is read-only global triage over cached/native fan, risk, LOC, and override signals. `kind=override` ranks virtual/override contracts by signature-aware child overrides and overridden parents, using `source_override_edges` when available. It exposes `input`, `limits`, `hotspots[]`, optional `questions[]`, `truncated`, and `next_actions`, and intentionally avoids community/betweenness semantics.
- `source.find_unused` is read-only advisory dead-symbol discovery over `symbols`, quoted `"references"`, and `inheritance`. It exposes `input`, `limits`, capped `items[]`, `confidence`, `reasons[]`, `truncated`, and `next_actions`; it must be recall-first (`min_confidence=low`) by default because UE reflection, delegates, Blueprint references, and soft-path references are outside the graph.
- `source.review_context` is a dedicated CRG-style review package distinct from single-item `bridge.build_attachment`; it exposes `input`, `limits`, `risk`, `top_risks[]`, `impact`, compact `context[]`, `truncated`, and `next_actions`. Seed and context rows include `path_status=known|missing`, seed lookup prefers known paths over missing-path duplicates, and top impacted rows keep the known-path variant when the same qualified/kind/file identity also appears as missing. Its impact summary includes override edges by default through `call|type|inheritance|override`.
- `source.search_crg_graph` is a read-only compatibility surface over the EngineSource `source_graph_nodes` VIEW/FTS. Live MCP must refuse the request while source indexing is active, verify subsystem DB readiness, and delegate with the subsystem's exact DB path as `--source-db`; direct CLI and live MCP therefore share one ranking, fallback, de-duplication, and response implementation over the same selected DB. LIKE is permitted only after a successfully executed FTS query returns zero rows. FTS prepare/step failure must remain observable as a structured warning/error with empty results and must not be reinterpreted as a zero-hit. It never opens, creates, repairs, or exports a second database. Standalone Query rejects normalized `graph_db` globally before catalog/path/DB work, regardless of namespace or action.
- `bridge.search_asset_symbols` is the RX-6 cross-DB bridge. It remains read-only in editor and offline CLI paths: it never writes ProjectIndex, EngineSource, CRG cache, graph-node FTS, or snapshots; it never shells out to P4/git; and it must degrade with `warnings[]` when either index is unavailable or currently indexing. The bridge requires exactly one non-empty string seed (`asset_path` or `symbol`) and rejects wrong-typed seeds with `-32602` instead of silently selecting the other mode. The bridge is heuristic rather than authoritative: asset-seeded lookups derive candidate native class names from the package path, asset name, asset class, and common UE prefixes/suffixes, then search EngineSource symbols with bounded exact-name/FTS queries before score-sorting and trimming; symbol-seeded lookups search source symbols first and then ProjectIndex assets by exact/normalized names, evaluating the bounded symbol set before global score sorting rather than stopping on a pre-ranking candidate cap. Duplicate asset/symbol pairs preserve the highest-scoring candidate so an early lexical hit cannot block a later exact/normalized hit.
