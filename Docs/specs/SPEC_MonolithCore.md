### Classes

| Class | Responsibility |

| `FMonolithCoreModule` | IModuleInterface. Starts HTTP server, registers core tools, owns `TUniquePtr<FMonolithHttpServer>` |
| `FMonolithHttpServer` | Embedded MCP HTTP server. JSON-RPC 2.0 dispatch over HTTP. Fully stateless (no session tracking). `tools/list` response embeds per-action param schemas in the `params` property description (`*name(type)` format, `*` = required) so AI clients see param names without calling `monolith_discover` first |
| `FMonolithExecutionContext` / `FScopedMonolithExecutionContext` | Central per-MCP-request execution context (UnrealMCP gap spec M4 foundation, `Spec/04`). Carries redacted JSON-RPC id / ToolCall id / session id, protocol version, client name, namespace/action, progress token, started-UTC, and a thread-safe cancellation flag (`RequestCancellation()` / `IsCancellationRequested()`, `ToJson()` for redacted status). `FScopedMonolithExecutionContext` is the RAII scope that publishes/restores the current thread-local context (nesting-safe; `GetCurrent()` / `HasCurrent()`). **Wired into dispatch:** `HandleToolsCall` constructs and scopes a context around `ExecuteAction`, and `FMonolithActionExecutionGuard::EndAction` consumes `GetCurrent()` so ToolCall records carry the real `json_rpc_id` / `tool_call_id` / `progress_token` / redacted session (off-dispatch callers leave it null and keep the `unknown`/`stateless` defaults). Cancellation/progress consumption still lands in follow-up slices; legacy handlers are unchanged. Static helpers: `RedactSessionId` (SHA-256, never leaks the raw id), `GenerateLocalToolCallId`, `ExtractProgressToken` (reads params `_meta.progressToken`), `JsonRpcIdToString` |
| `FMonolithCancellationRegistry` / `FScopedMonolithCancellationRegistration` | Thread-safe registry of in-flight MCP request ids cancellable across threads (UnrealMCP gap spec M4). `notifications/cancelled` arrives as a separate request (possibly on another thread), so cancellation is routed by request id through this registry rather than the thread-local execution context. `HandleToolsCall` RAII-registers the request id around `ExecuteAction`; the `notifications/cancelled` handler calls `RequestCancellation(requestId, reason)`. Opt-in long-running actions poll `IsCancellationRequested(GetCurrent()->GetJsonRpcId())` and abort cooperatively — cancellation transport, not preemption; synchronous actions are unaffected. |
| `FMonolithProgressRegistry` / `FScopedMonolithProgressRegistration` | Thread-safe per-`progressToken` registry of in-flight MCP progress (UnrealMCP gap spec M4). `HandleToolsCall` RAII-registers the request's `_meta.progressToken` (if any) around `ExecuteAction`; an opt-in long-running action calls `Report(token, progress, total, message)`. Latest state is exposed read-only via the `monolith://progress/active` resource and `GetActiveJson()`. **Transport limitation:** real-time `notifications/progress` streaming is NOT delivered — the embedded UE HTTP server has no long-lived SSE (`HandleGetMcp` returns a single event and closes), so progress is poll-delivered via `resources/read` today; a push transport is a follow-up. |
| `FMonolithToolRegistry` | Central singleton action registry. `TMap<FString, FRegisteredAction>` keyed by "namespace.action". Thread-safe — releases lock before executing handlers. Validates ALL required params from schema before dispatch (including `asset_path`; K2 `ApplyAliases` canonicalizes declared aliases such as `system_path` into the canonical key first, so a missing required asset path surfaces the structured `missing_required_param` contract — `failure_cause`/`retryability`/`missing_required_params` — rather than a handler's ad-hoc "not found" message). Returns descriptive error listing missing + provided keys. **Blueprint script-exception capture (`FMonolithScriptExceptionScope`):** `ExecuteAction` wraps the handler call in an RAII scope subscribed to `FBlueprintCoreDelegates::OnScriptException`; a handler that returns Success while a Blueprint/Kismet script error fired (`RaiseScriptError`, access-none, array-bounds, etc.) is converted to a structured error (`error.data.failure_cause = "blueprint_script_exception"`, `script_exception` = message). Debug/trace exception types (Breakpoint/Tracepoint/WireTracepoint) are ignored, and pure-C++ handlers with no active script frame are unaffected. Mirrors UE 5.8 ToolsetRegistry `FToolCallExceptionHandler` |
| `FMonolithJsonUtils` | Static JSON-RPC 2.0 helpers. Standard error codes (-32700 through -32603). Declares `LogMonolith` category |
| `FMonolithAssetUtils` | Asset loading with 4-tier fallback: StaticLoadObject(resolved) -> PackageName.ObjectName -> FindObject+_C suffix -> ForEachObjectWithPackage |
| `UMonolithSettings` | UDeveloperSettings (config=Monolith). ServerPort, bAutoUpdateEnabled, DatabasePathOverride, EngineSourceDBPathOverride, EngineSourcePath, 10 module enable toggles + `bEnableProceduralTownGen` (experimental, default false) (functional — checked at registration time), LogVerbosity. Settings UI customized via `FMonolithSettingsCustomization` (IDetailCustomization) with re-index buttons for project and source databases |
| `UMonolithUpdateSubsystem` | UEditorSubsystem. GitHub Releases auto-updater. Shows dialog window with full release notes on update detection. Downloads zip, cross-platform extraction (PowerShell on Windows, unzip on Mac/Linux). Stages to Saved/Monolith/Staging/, hot-swaps on editor exit via FCoreDelegates::OnPreExit. Current version always from compiled MONOLITH_VERSION (version.json only stores pending/staging state). Release zips include pre-compiled DLLs. |
| `FMonolithCoreTools` | Registers the curated public core tools (`discover`, `status`, `update`, `reindex`, `guide`) and serves focused `monolith_discover` modes. |
| `FBulkFillSpec` | USTRUCT (`BlueprintType`). Input shape for `bulk_fill_query("apply")`: `target_namespace`, `target` (asset path or class), nested JSON `tree`, plus `dry_run` / `strict` toggles. Same shape consumed by every per-namespace adapter registered via `FMonolithBulkFillRegistry`. |
| `FDryRunReport` | USTRUCT (`BlueprintType`). Output shape returned when `dry_run=true`. Carries per-field `FieldWrites`, `SilentDrops` (with reason — covers `FGameplayAttribute`-rename hazard class and other type-mismatch / unknown-field cases), `Clamps` (engine clamp annotations such as the AI `lose_sight_radius >= 1.1 × sight_radius` rule), `Errors`. Promoted to hard error and transaction-rollback when `strict=true`. |
| `FSchemaDescriptor` | USTRUCT (`BlueprintType`). Output shape returned by `describe_query("schema")`. Recursive tree of `FFieldDescriptor` nodes: type name, ImportText sample form, `range_min` / `range_max`, `enum_values`, `conditional_on` discriminators (for tagged-union fields like GE modifier magnitudes), nested struct/array/map/set children. Authoritative source for legal `set_cdo_properties` / `bulk_fill` payload grammar. |
| `FMonolithReflectionWalker` | **Write-side** reflection-walker primitive that drives every bulk-fill adapter. Recursively walks UE 5.7 `FProperty` / `FStructProperty` / `FArrayProperty` / `FMapProperty` / `FSetProperty` / `FObjectProperty` / `FSoftObjectProperty` / `FEnumProperty` against a JSON tree. `InspectTree(...)` returns an `FDryRunReport` without mutation; `ApplyTree(...)` performs the writes under the caller-owned transaction. Single source of truth for ImportText parsing, type coercion, and clamp/enum validation. (Has no FProperty→JSON *reader* — that is the complementary `FMonolithReflectionReader` below.) |
| `FMonolithReflectionReader` | **Read-side** counterpart to `FMonolithReflectionWalker` (new 2026-06-07; `Reflection/MonolithReflectionReader.{h,cpp}`). Static helper `PropertyToJsonValue(FProperty*, const void* ValuePtr)` (+ a `PropertiesToJsonObject(UObject*)` convenience) that serializes an `FProperty` value to JSON — handling `FSoftObjectProperty` / `FSoftClassProperty` / `FStructProperty` recursion / `FArrayProperty` / `FInstancedStruct` / gameplay-tag structs. Pure reflection read (no mutation, no transaction, never dirties a package). **Dedup:** this single implementation replaced two prior copies of the same serializer — the CDO-action copy (`MonolithCDOInternal::PropertyToJsonValue` in `MonolithBlueprintCDOActions.cpp`) and the DataAsset-indexer copy (`FDataAssetIndexer::PropertyToJsonValue` in `MonolithIndex`). Both call sites plus `seed_data_asset`'s `read_back_values` and `get_cdo_properties` now share this one reader. Deliberately a separate file from the write-side walker so the read/write split stays legible. |
| `FMonolithBulkFillRegistry` | String-keyed singleton dispatcher. Per-namespace adapters call `RegisterAdapter(namespace, fn)` from their owning module's `StartupModule`; the central `bulk_fill_query("apply")` / `describe_query("schema")` handlers look up the adapter by `target_namespace` and delegate. **Zero compile-time linkage from `MonolithCore` into adapter modules** — preserves the Issue #30 / #32 hazard class (no hard imports of optional/conditional sibling modules). When a namespace adapter is absent or its module-level `WITH_*` gate is off, the registry returns a typed error rather than silently no-op'ing. |
| `FMonolithDryRunGuard` | RAII helper toggling the dry-run mode on a per-call basis. Adapters opt into the framework's `dry_run:true` preview-without-persist semantics by constructing this guard at the top of `ApplyTree`; on destruction the guard discards any provisional writes if dry-run was set. |
| `FMonolithAsyncJobRegistry` | Process-wide singleton (`Get()`) bounded in-memory registry for long-running async Monolith jobs (`Public/MonolithAsyncJobRegistry.h`). `SubmitJob(Namespace, Action)` mints a lowercase-hyphen GUID job id and seeds a `Pending` row; `UpdateProgress` advances `Pending`/`Running` rows (clamps percent to 0–100, never overwrites a terminal state); `CompleteJob`/`FailJob` set the terminal `Completed`/`Failed` row; `RequestCancel` sets a **cooperative** cancel flag and flips a non-terminal row to `Cancelled` (the registry never interrupts running work — the action polls `IsCancelRequested`). `GetJobJson` returns the row (or `{"status":"not_found"}`), `ListJobsJson` returns up to a clamped `1..1000` rows ordered by `UpdatedUtc` desc. Capacity is fixed at 128 rows; `SubmitJob` evicts the oldest-`UpdatedUtc` row when full. Thread-safe via one `FCriticalSection`. Stores only coarse status/progress metadata plus an optional result/error `FJsonObject`; spawns no threads, owns no workers, and does not persist across editor restarts. Lives in `Public/` so MonolithAI (ZoneGraph rebuild producer) and other modules can include it. See [SPEC_MonolithAsyncJobRegistry.md](SPEC_MonolithAsyncJobRegistry.md) / [SPEC_MonolithAsyncJobActions.md](SPEC_MonolithAsyncJobActions.md). |
| `FMonolithToolContentBlock` | Typed-media content-block struct (`Public/MonolithToolRegistry.h`) mirroring the MCP content-block shape: `Type` (`"image"`/`"audio"`), `MimeType`, `Base64Data`, and an optional `Audience` MCP annotation. `FMonolithActionResult` carries a `TArray<FMonolithToolContentBlock> MediaBlocks` slot that is **empty by default**, so existing responses stay byte-identical. `FMonolithToolResultUtils::BuildMcpToolResult(...)` only appends media blocks (after the always-present text block, and only `image`/`audio` types) when its `bEnableTypedMedia` argument is true — wired at the call site to `UMonolithSettings::bEnableTypedMediaResults` (default off, kept separate from `bEnableStructuredToolResults`). First adopter: `imagegen.generate_image`. See [SPEC_MonolithTypedMediaResults.md](SPEC_MonolithTypedMediaResults.md). |
| `FMonolithResourceRegistry` blob resources + `IMonolithResourceProvider` seam | The read-only MCP resource registry (`Public/MonolithResourceRegistry.h`) adds two capabilities beyond static text descriptors. **P3a blobs:** `RegisterBlobResource(Descriptor, BlobBytes, MaxBytes=1MiB)` stores bounded binary bytes eagerly and serves them as a base64 `"blob"` field instead of `"text"` (`FMonolithResourceReadResult::bBinary`/`BlobBytes`; text reads stay byte-identical with `bBinary=false`). **P3b provider seam:** `IMonolithResourceProvider` (`Public/IMonolithResourceProvider.h`) lets a namespace module contribute a bounded URI **family** (e.g. `monolith://source/file/{path}`) via `ListResources` (one/few stable template descriptors, no unbounded scan) and `ReadResource` (resolve one URI it owns, else return false). Providers are code-registered via `RegisterProvider`/`UnregisterProvider`, consulted only AFTER the static-descriptor and eager-blob branches miss (so a provider never shadows an explicit resource), and invoked OUTSIDE the registry lock. First concrete provider lives in MonolithSource. Whole surface gated by `UMonolithSettings::bEnableMcpResources` (default off). See [SPEC_MonolithMcpResources.md](SPEC_MonolithMcpResources.md) / [SPEC_MonolithSourceResourceProvider.md](SPEC_MonolithSourceResourceProvider.md). |
| MCP session-mode promotion (P1c) | `FMonolithMcpSessionTracker` (`Public/MonolithMcpSessionTracker.h`) is promoted from a bounded request observer toward the MCP Streamable HTTP lifecycle contract, reusing the existing `UMonolithSettings::bEnableMcpSessionMode` flag (no new flag). Each session row gains additive `lifecycle_status` (`initializing`/`initialized`/`observed`) plus a redacted `client_capabilities` object (`roots`/`sampling`/`elicitation` booleans) — existing keys stay byte-identical. The server enforces a session gate around the per-request loop and tracks a tool-list revision so `initialize` can advertise `tools.listChanged`. Raw session ids, params, and capability objects are never stored; with the flag off the wire behavior early-returns to legacy. Server-push `notifications/tools/list_changed` delivery is deferred (single-shot SSE has no long-lived push channel). See [SPEC_MonolithMcpSessionModeGate.md](SPEC_MonolithMcpSessionModeGate.md). |

| Action | MCP Tool | Description |

| `update` | `monolith_update` | Check/install updates from GitHub Releases. `action`: "check" or "install" |

| `guide` | `monolith_guide` | Section-keyed editorial guide from `Docs/MONOLITH_GUIDE.md` with live registry overlay. It explains workflow intent and recovery; it does not replace `monolith_find`, `monolith_discover`, or `describe`. |

| `cancel_job` | `monolith_cancel_job` | Request cooperative cancellation of an async job by `job_id` and return its current row (mutation, idempotent, non-destructive). Gated by `bEnableAsyncJobs`: with the flag off it returns `{status:"disabled", requested_job_id, cancel_requested:false, reason}`; with the flag on it sets the cooperative cancel flag (the running action must observe it) and returns the post-request row. Required param: `job_id` (string). |

### Actions (2 — namespace: "bulk_fill")

Framework-level dispatchers for transacted JSON-tree writes against any registered per-namespace adapter. Adapters live in their owning modules (`MonolithBlueprint`, `MonolithGAS`, `MonolithUI`, `MonolithAI`, `MonolithNiagara`, `MonolithMaterial`, `MonolithAudio`, `MonolithMesh`, `MonolithAnimation`, `MonolithLogicDriver`, `MonolithComboGraph`, and an optional sibling-plugin `inventory` adapter); `MonolithCore` owns only the framework primitives and the dispatch surface.

| Action | MCP Tool | Description |
|--------|----------|-------------|
| `apply` | `bulk_fill_query` | Apply a JSON `tree` to `target` under `target_namespace`. Routes to the per-namespace adapter via `FMonolithBulkFillRegistry`. Params: `target_namespace` (string), `target` (asset path or class identifier), `tree` (nested JSON), `dry_run` (bool, default false — returns full `FDryRunReport` without mutation), `strict` (bool, default false — promotes silent drops / clamps / unknown-fields to hard errors and cancels the transaction). Returns the populated `FDryRunReport` either way. |
| `list_namespaces` | `bulk_fill_query` | Enumerate registered adapter namespaces and their `available` flag (false when the owning module's `WITH_*` gate is off — e.g. `gas` adapter `available:false` when `WITH_GBA=0`). No params. Use before `apply` to confirm the target namespace is hot in the current build. |

### Actions (3 — namespace: "describe")

Read-only schema introspection companion to `bulk_fill`. Uses the same adapter registry.

| Action | MCP Tool | Description |
|--------|----------|-------------|
| `schema` | `describe_query` | Return the rich `FSchemaDescriptor` tree for `target_namespace`, optionally scoped to `target`. Params: `target_namespace` (optional string; aliases `namespace`, `domain`), `target` (optional asset path or action/class identifier). Omitting `target` returns the namespace-level writable-shape descriptor. Omitting or misspelling `target_namespace` returns structured guidance (`match_status=namespace_index` / `no_adapter`, `available_namespaces`, `next_actions`) instead of a validation dead-end. Output includes ImportText sample forms, `range_min` / `range_max`, `enum_values`, `conditional_on` discriminators for tagged-union fields. Authoritative input source for authoring valid `bulk_fill.apply` payloads. |
| `list_targets` | `describe_query` | Optional inventory for a namespace adapter. Params: `target_namespace` (optional string; aliases `namespace`, `domain`). Adapters may return `inventory_supported=false` / `optional_inventory_not_implemented`; omitted or unknown namespaces return registered namespace guidance. Use `bulk_fill.list_namespaces` plus `describe.schema` to confirm adapter support. |
| `action_schema` | `describe_query` | Return a registered ACTION's param schema (names, types, required, defaults, aliases, descriptions) by `(target_namespace, target_action)`. Params: `target_namespace` (string), `target_action` (string). Closes param-name discoverability so callers stop trial-and-erroring param names. |
