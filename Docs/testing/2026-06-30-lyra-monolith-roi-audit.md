## 1. Summary

Speed already has broad low-level Monolith coverage for GameFeatureData actions, Enhanced Input mappings, CommonUI activatable widgets, UI extension points, world settings property writes, editor validation, source control path mapping, project search, and source search.

The remaining high-ROI work is not more project-specific commandlet logic. The highest value is to add reusable Lyra/CommonGame-level semantic actions that compose existing primitives and validate the full asset contract. This would replace most of `SPDTagChaseSetupCommandlet` and reduce future one-off editor commandlets.

`PrimaryGameLayout` runtime code should not be modified for this work. Monolith already has `ui.add_primary_game_layout_layer`; future work should improve Monolith composition and validation actions instead of changing `CommonGame` runtime behavior.

The subagent re-audit did not change the P0 direction, but it sharpened the implementation package list. The next Monolith-only work should be new generic modules/namespaces and deeper semantic validators, not Speed-only wrappers.

## 6. Non-Recommendations

| Candidate | Decision | Reason |
| --- | --- | --- |
| More raw GameFeature `add_*` actions | Defer unless a specific missing Unreal action class appears. | Existing writer coverage already handles scans, widgets, input mappings, components, cue paths, abilities, and removals. |
| More raw CommonUI activatable CRUD | Defer. | Activatable widget/stack/switcher/configure actions already exist. Higher ROI is Lyra/CommonGame composition validation. |
| More raw editor validation wrappers | Defer. | `editor.validate_assets` already exists. The gap is a changeset planner and project-specific settings adapters, not another generic `ValidatePackages` wrapper. |
| More raw P4 opened/path actions | Defer. | `source_control.map_depot_paths` exists. The gap is mapping those results into validation/build review workflows. |
| GameSettings/LoadingScreen as only `ui.get_common_framework_status` expansion | Defer. | Availability reflection exists. The missing value is semantic registry-tree, data-source, loading-processor, and reason-contract validation. |
| Runtime `PrimaryGameLayout` code edits | Do not do this for Monolith capability work. | Monolith should author/inspect/validate assets and config. Runtime CommonGame code should only change for actual game behavior requirements. |
| Project-specific Speed-only actions | Avoid. | The useful pieces are reusable across Unreal, Lyra, and common plugins. Project-specific data should be action input, not baked into Monolith. |

## 7. Done Criteria For Remaining Implementation

| Capability | Minimum acceptance criteria |
| --- | --- |
| Lyra Experience graph | Dry-run and write modes, asset save support, idempotent comparisons, validation output with exact missing asset/path/property, tests against a small Lyra fixture or Speed assets. |
| Package graph copy/remap | Dry-run plan, explicit source/destination root map, optional safe content mount registration, explicit strategy selection, no silent fallback copy path, hard and soft reference fixup, dependency closure report, no legacy source-root dependencies unless explicitly allowed. |
| UI/BP copy repair | Source and destination package map input, class/object remap table, copied widget/Blueprint graph clone report, compile/save result, and actionable errors for missing classes or invalid graph ownership. The Blueprint clone action contract is `blueprint.clone_graphs_with_reference_remap`: `source_asset_path`, `destination_asset_path`, single `graph_name`/`new_name` or batch `graphs[]`, `class_remaps`, `object_remaps`, `root_remaps`, `source_root` + `dest_root`, default `dry_run=true`, `confirm=true` required for writes, `existing_policy` values `fail`/`replace`/`skip`, optional `compile`, `save`, and `allow_empty_remap`; support is limited to function/macro graphs. |
| EOS/CommonSession diagnostics | No secret values in logs or JSON output, config-layer provenance, OSSv2/CommonUser path confirmation, lobby schema/session attribute checks, actionable missing-setting messages. |
| Gameplay phase/message validators | Tag domain discovery, static broadcaster/listener/payload graph, phase transition checks, payload mismatch candidates, orphan broadcaster/listener candidates, unresolved channel candidates, and match-type ambiguity candidates. Runtime listener state and live reachability proof remain explicit runtime verification work. |
| CommonUser/CommonGame diagnostics | Reflected class availability, configured subclass discovery, modal layer validation, login/privilege state graph, OSS branch identification, and no credential logging. |
| GameSettings/loading diagnostics | Registry tree dump, duplicate-name checks, data-source getter/setter resolution, mappable-input coverage, loading processor/reason graph, and CVar/config provenance. |
| Automation wrappers | Engine root resolved from `.uproject` `EngineAssociation`, explicit dry-run/manifest modes, no secrets in upload notifications, and no root-level `BatchFiles` wrappers. |
