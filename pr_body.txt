- 💡 What:
  Added `.Reserve()` calls to five fixed-size `TArray` collections (`Inputs`, `Outputs`, `EventTypes`) inside the `HandleProposeHooks` stub in `MonolithMeshQualityActions.cpp` before sequential `.Add()` operations.

- 🎯 Why:
  Sequential `.Add()` calls without a prior `.Reserve()` trigger unnecessary heap allocations and array re-copying as the array dynamically resizes. Since the number of elements is known and static (2, 3, or 5 elements), pre-allocating the correct capacity avoids this waste.

- 📊 Impact:
  Static/algorithmic estimate: Prevents 5-10 small heap allocations per execution of the `hook_propose` action.

- 🔬 Measurement:
  Not available (UE/editor benchmark unavailable). proxy metric: fewer allocations.
