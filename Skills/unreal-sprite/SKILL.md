# unreal-sprite

Drives the upstream sprite-asset production contract (asset_spec validation, guide readiness, candidate planning, request batching, sheet/atlas QA, metadata export) before finished textures are handed to Paper2D, UI, Niagara, or gameplay. Drives the Monolith MCP `sprite` namespace via `sprite_query(action, params)`. **9 actions** across status, M1 read/validate, M2 package/export, and M3 orchestration; the tables below are a snapshot of the live registry surface, so call `monolith_discover` for exact parameter schemas before invoking.

## Discovery

```
monolith_discover({ namespace: "sprite" })                                      # all actions in this namespace
monolith_discover({ namespace: "sprite", action: "<action>", mode: "schema" })  # exact params
```

When the right action is unclear, `monolith_find("<task>")` suggests candidates across namespaces. Production spec: `Docs/specs/SPEC_MonolithSprite.md`.

## When to use / Use a different skill for

- **This skill:** the sprite-sheet production contract itself - `asset_spec.yaml` validation, guide-readiness checks, candidate-batch planning, imagegen request preparation, final sheet/atlas validation, and metadata export, plus the profile rules for `pc_character`, `npc_character`, `monster_character`, `item_icon`, `skill_icon`, `world_pickup_sprite`, and `effect_sprite`.
- **unreal-paper2d** — building the runtime Paper2D asset (PaperSprite, PaperFlipbook, PaperTileSet, PaperTileMap) from a finished sprite sheet, after this production step completes.
- **unreal-asset** — the generic Texture2D ingest/save/rename/move/delete/metadata step, versus the sprite_spec / candidate-selection / postprocess production workflow.
- **unreal-imagegen** — generating the raw sprite image with AI (prompt-to-PNG, ima2 bridge, import generated bytes) before it is run through this production pipeline.
- **unreal-ui** — handing a finished icon/sprite into a UMG widget (icon atlas, skill icon), versus producing the sprite sheet.

## Action Reference

Param notation: `name*` required, `name?` optional, `name=val` default, `a/b/c` allowed, `[w]` mutates. Signatures are a snapshot of the live catalog — for the exact full schema call `monolith_discover` with `mode: "schema"`. Keep the discover-first block above as the authority. The spec arg is `spec_path` (path to `asset_spec.yaml`), not `asset_spec`.

### Status (1)

| Action | Params | Purpose |
|--------|--------|---------|
| `get_status` | _(none)_ | Report MonolithSprite orchestration status, supported profiles, and action ownership boundaries. |

### M1 read/validate (3)

| Action | Params | Purpose |
|--------|--------|---------|
| `validate_asset_spec` | `spec_path*` | Validate one `asset_spec.yaml` against the profile contract (profile, target surface, dimensions, frame contract, texture role, profile-specific fields). Read-only; no generation or asset mutation. |
| `validate_guides` | `spec_path*` | Check that the pose/silhouette/composition guide PNGs required by the chosen profile exist and match the declared work canvas. |
| `build_candidate_plan` | `spec_path*` | Build a deterministic per-frame/per-seed candidate generation plan without calling a provider. |

### M2 package/export (3)

| Action | Params | Purpose |
|--------|--------|---------|
| `validate_sheet` | `spec_path*` `sheet_path*` `metadata_path?` | Verify the final sheet/atlas dimensions, cell grid, frame capacity, and alpha coverage against the spec. `metadata_path` is an optional JSON path checked for existence. |
| `export_metadata` | `spec_path*` `output_path?` `sheet_path?` | Export deterministic sheet/atlas metadata JSON (cell rects, pivots, frame ids, role, source spec path). `output_path` defaults to `export/<asset_id>_metadata.json`; `sheet_path` is the optional final PNG recorded in metadata. |
| `build_preview_contact_sheet` | `spec_path*` `output_path?` `thumbnail_size?=256` | Build a guide preview PNG from pose/silhouette/composition guides for review. `output_path` defaults to `export/<asset_id>_guide_preview.png`. Does not mutate Unreal assets. |

### M3 orchestration (2)

| Action | Params | Purpose |
|--------|--------|---------|
| `prepare_imagegen_requests` | `spec_path*` | Prepare `imagegen.generate_image_via_ima2` request payloads from a validated spec. Does not call the provider. |
| `run_generation_batch` | `spec_path*` `execute?=false` `provider_action?` `max_requests?` `manifest_path?` `stop_on_error?` | Execute a prepared candidate batch by delegating each request to a provider, then write a generation manifest. `execute` must be `true` to call providers (false returns a dry-run plan); `provider_action` overrides the request action (e.g. `imagegen.generate_image_via_ima2`); `max_requests` caps requests (default all); `manifest_path` defaults to `export/<asset_id>_generation_manifest.json`; `stop_on_error` defaults true. |

## Common Workflows

```
# 1. Validate the production contract before any generation.
sprite_query("validate_asset_spec", { "spec_path": "Docs/assets/hero_knight_v01/asset_spec.yaml" })

# 2. Confirm the profile's required guide files exist per frame.
sprite_query("validate_guides", { "spec_path": "Docs/assets/hero_knight_v01/asset_spec.yaml" })

# 3. Build the candidate generation plan, then prepare imagegen requests (dry-run).
sprite_query("build_candidate_plan", { "spec_path": "Docs/assets/hero_knight_v01/asset_spec.yaml" })
sprite_query("prepare_imagegen_requests", { "spec_path": "Docs/assets/hero_knight_v01/asset_spec.yaml" })

# 4. Execute the batch only when ready (delegates to imagegen).
sprite_query("run_generation_batch", { "spec_path": "Docs/assets/hero_knight_v01/asset_spec.yaml", "execute": true })

# 5. Validate the assembled sheet and export metadata for runtime import.
sprite_query("validate_sheet", { "spec_path": "Docs/assets/hero_knight_v01/asset_spec.yaml", "sheet_path": "Docs/assets/hero_knight_v01/export/hero_knight_sheet.png" })
sprite_query("export_metadata", { "spec_path": "Docs/assets/hero_knight_v01/asset_spec.yaml" })
```

## Gotchas / Rules

- `MonolithSprite` orchestrates and validates only — it does not duplicate provider code, Texture2D import code, or Paper2D asset mutation. It hands off to the owning module: raw image generation to `unreal-imagegen`, Texture2D ingest/role postprocess to `unreal-asset`, runtime sprite/flipbook assembly to `unreal-paper2d`.
- `prepare_imagegen_requests` is dry-run by default; `run_generation_batch` mutates/generates only with `execute=true`. Plan and review before executing a batch.
- Import accepted outputs with `texture_role` set to `sprite`, `ui_icon`, or `decal` per profile (`ui_icon` for UI-only item/skill icons; `sprite` for Paper2D/PaperZD sheets, billboards, pickups, and VFX flipbooks; `decal` for decal-style effects).
- Do not bake UI frames, cooldown numbers, hotkeys, or text into icons unless the asset spec explicitly requires it. Keep canvas, lighting, baseline, pivot, and identity stable across animation frames; declare blend mode, flow direction, impact center, and frame energy for effects before generation.
- Keep the final sprite-sheet Texture2D dimensions power-of-two when practical. For 256px four-direction character sheets prefer `4x4=1024x1024` or `8x4=2048x1024` over non-power-of-two widths such as `6x4=1536x1024` unless the source art or runtime contract requires otherwise.
- When removing a background, only remove background pixels connected to the image/cell border via flood-fill or connected-component logic; do not globally delete a color that may exist inside the subject.
- This reference is generated from the live `RegisterAction` surface. If an action is missing or renamed, re-run `monolith_discover({ namespace: "sprite" })` — the catalog is the source of truth.
